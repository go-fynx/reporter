# Reporter API

How a service sends log and error events to the reporter service. Go services use the reporter-go SDK, which speaks gRPC; see [sdk.md](sdk.md). Services in other languages can send plain HTTP requests with JSON, as described here.

The contract is defined in [reporter.proto](../reporter-go/proto/reporter/v1/reporter.proto). That file is the source of truth if this page and the proto ever disagree.

## Endpoint

| | |
|---|---|
| URL | `https://<reporter-host>:8443/reporter.v1.ReporterService/Notify` |
| Method | `POST` |
| Content type | `application/json` (or `application/proto` for binary protobuf) |
| Authentication | `Authorization: Bearer <api key>` |
| Protocols on the same port | gRPC (HTTP/2), plain HTTP/1.1 or HTTP/2 POST with JSON or protobuf |

Each project gets its own API key. An operator creates it with `reporter keygen` (see [service.md](service.md#api-keys)). The key determines which project an event belongs to; the request body cannot change that.

## Example

```sh
curl -sS https://reporter.internal:8443/reporter.v1.ReporterService/Notify \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $REPORTER_API_KEY" \
  -d '{
    "source": {
      "service": "billing-worker",
      "environment": "production",
      "appVersion": "2.0.1",
      "hostname": "worker-3",
      "sdkName": "billing-python-client",
      "sdkVersion": "0.1.0"
    },
    "events": [
      {
        "eventId": "0195f1c8-6b2e-7a3c-9d4e-5f6a7b8c9d0e",
        "timestamp": "2026-11-12T08:58:49.120Z",
        "severity": "SEVERITY_ERROR",
        "unhandled": false,
        "message": "invoice could not be sent: connection refused",
        "errorType": "ConnectionRefusedError",
        "stack": [
          {"function": "send_invoice", "file": "billing/send.py", "line": 42, "inProject": true}
        ],
        "causes": [
          {"errorType": "OSError", "message": "[Errno 111] Connection refused"}
        ],
        "attributes": {
          "invoice_id": {"stringValue": "inv_123"},
          "attempt": {"intValue": "2"},
          "amount": {"doubleValue": 19.99},
          "retry_scheduled": {"boolValue": true}
        }
      }
    ]
  }'
```

Response:

```json
{"acceptedCount": 1}
```

## Request

### `source`: who is reporting (once per request)

| Field | Required | Notes |
|---|---|---|
| `service` | yes | 1 to 100 letters, digits, `.`, `_` or `-`, starting with a letter or digit |
| `environment` | no | Same characters as `service`; stored in lowercase. Defaults to `production` |
| `appVersion`, `hostname`, `os`, `runtimeVersion`, `sdkName`, `sdkVersion` | no | Free text, at most 256 bytes each |

### `events[]`: up to 100 per request

| Field | Required | Notes |
|---|---|---|
| `eventId` | yes | A UUID generated by the client when the event happens. UUIDv7 is preferred because it sorts by time. Any case and the standard UUID forms are accepted. |
| `timestamp` | yes | When the event happened, RFC 3339 in UTC, for example `2026-11-12T08:58:49.120Z`. May be at most 24 hours in the future. Stored with millisecond precision. |
| `severity` | yes | `SEVERITY_INFO`, `SEVERITY_WARNING` or `SEVERITY_ERROR` |
| `message` | one of these two | Human-readable text |
| `errorType` | one of these two | Error class or type name |
| `unhandled` | no | `true` for crashes and panics nobody caught |
| `stack` | no | Frames, innermost call first: `function`, `file`, `line`, `inProject`. At most 256 frames. |
| `causes` | no | Wrapped or chained errors, outermost first: `errorType`, `message`, `stack`. At most 32. |
| `attributes` | no | Up to 100 entries. Keys are 1 to 128 bytes. Each value sets exactly one of `stringValue`, `intValue`, `doubleValue` or `boolValue`. |

JSON details:
- Field names may be written in camelCase (`eventId`) or snake_case (`event_id`).
- 64-bit integers (`intValue`) should be sent as strings, for example `"2"`. Numbers are also accepted.
- Unknown fields are ignored, so a client built against a newer contract still works with an older service.
- Strings must be valid UTF-8.

## Response

| Field | Meaning |
|---|---|
| `acceptedCount` | Events that were stored |
| `rejections[]` | Events that were not stored, each with `index` (position in `events`, starting at 0), `eventId`, `reason` and `detail` |

**Fields with a zero value are left out of JSON responses.** When nothing was accepted there is no `acceptedCount`. A rejection of the first event has no `index`. Treat a missing number as 0.

A request can succeed with some events rejected; only the valid ones are stored. A successful response means every accepted event has been written to the database.

Rejection reasons:

| Reason | Cause |
|---|---|
| `REJECTION_REASON_INVALID_EVENT_ID` | `eventId` missing or not a UUID |
| `REJECTION_REASON_DUPLICATE_EVENT_ID` | The same `eventId` appears twice in one request |
| `REJECTION_REASON_INVALID_TIMESTAMP` | `timestamp` missing, out of range or too far in the future |
| `REJECTION_REASON_INVALID_SEVERITY` | `severity` missing or unknown |
| `REJECTION_REASON_MISSING_MESSAGE` | Neither `message` nor `errorType` is set |
| `REJECTION_REASON_INVALID_ATTRIBUTE` | An attribute key is empty or too long, or a value sets none of the four types |
| `REJECTION_REASON_TOO_MANY_ATTRIBUTES` | More than 100 attributes |
| `REJECTION_REASON_TOO_MANY_CAUSES` | More than 32 causes |
| `REJECTION_REASON_TOO_MANY_FRAMES` | More than 256 frames in the stack or in a cause |

The limits above are the service defaults; operators can change them.

## Errors

When the whole request fails, the response has a non-200 status and a JSON body such as `{"code": "unauthenticated", "message": "invalid API key"}`. gRPC clients receive the same codes as gRPC status codes.

| HTTP | `code` | Cause | Send again? |
|---|---|---|---|
| 400 | `invalid_argument` | Malformed JSON; missing or invalid `source.service` or `source.environment`; no events; more than 100 events | No; fix the request |
| 401 | `unauthenticated` | Missing, malformed or unknown API key | No; fix the key |
| 429 | `resource_exhausted` | The project's rate limit was exceeded, or the request is larger than 1 MiB | Rate limit: later, with backoff. Too large: no; split it |
| 503 | `unavailable` | The service is at its concurrent-request limit, or the database is unavailable | Later, with backoff |
| 500 | `internal` | Unexpected server error | Later, with backoff |

Resending is safe. An event sent again with the same `eventId` is stored once, so a client that times out without an answer can resend the same events.

## Health checks

| Path | Meaning |
|---|---|
| `GET /healthz` | 200 while the process is running |
| `GET /readyz` | 200 when the service is accepting events and the database is reachable; 503 otherwise, including during shutdown |

## Using the proto from other languages

Generate a gRPC or Connect client from `reporter-go/proto/reporter/v1/reporter.proto` with `buf generate` or `protoc`, and set the `Authorization: Bearer <api key>` header (gRPC metadata `authorization`) on every call.
